3. STANDARD REDEPLOY (MOST COMMON)
----------------------------------------------------------------------
When HTML/CSS/JS/server files change:

A) Upload changed files from a Windows PowerShell session
B) Rebuild and recreate the Docker container on EC2

PowerShell variables (reuse these):

  $pscp   = "C:\Program Files\PuTTY\pscp.exe"
  $plink  = "C:\Program Files\PuTTY\plink.exe"
  $key    = "C:\Users\JohanH\Feenstra Group\Systems - Johan Hattingh\Desktop\LadyMarcell.ppk"
  $remote = "ec2-user@15.252.165.172"
  $root   = "C:\Users\JohanH\TestWebsite\Lady-Marcell-site\LadyMarcell-V1"

Upload examples:

  # HTML pages
  & $pscp -i $key "$root\index.html" "$root\booking.html" "$root\croatia.html" "$root\montenegro.html" "${remote}:/home/ec2-user/LadyMarcell-V1/"

  # JS folder files
  & $pscp -i $key "$root\js\main.js" "$root\js\booking.js" "${remote}:/home/ec2-user/LadyMarcell-V1/js/"

  # CSS folder files
  & $pscp -i $key "$root\css\styles.css" "${remote}:/home/ec2-user/LadyMarcell-V1/css/"

  # Entire folder (careful — overwrites remote files)
  & $pscp -i $key -r "$root\js" "${remote}:/home/ec2-user/LadyMarcell-V1/"
  & $pscp -i $key -r "$root\css" "${remote}:/home/ec2-user/LadyMarcell-V1/"

Rebuild on server via plink (one command):

  & $plink -i $key -batch $remote "cd ~/LadyMarcell-V1 && docker stop lady-marcelle && docker rm lady-marcelle && docker build -t lady-marcelle . && docker run -d --name lady-marcelle -p 127.0.0.1:3000:3000 --env-file .env --restart unless-stopped lady-marcelle && sleep 2 && docker ps --filter name=lady-marcelle && curl -sI http://127.0.0.1:3000/ | head -5"

Or run the same Docker steps manually in PuTTY after SSH:

  cd ~/LadyMarcell-V1
  docker stop lady-marcelle
  docker rm lady-marcelle
  docker build -t lady-marcelle .
  docker run -d --name lady-marcelle -p 127.0.0.1:3000:3000 --env-file .env --restart unless-stopped lady-marcelle

IMPORTANT:
- Bind port as 127.0.0.1:3000:3000 (localhost only). Nginx is the public front.
- Always pass --env-file .env
- Always use --restart unless-stopped
- Do NOT delete or overwrite the server `.env` unless intentionally updating mail settings

5. ENVIRONMENT (.env ON SERVER ONLY)
----------------------------------------------------------------------
Location on EC2: /home/ec2-user/LadyMarcell-V1/.env
Template locally: .env.example

Typical keys (values live only on server):
  PORT=3000
  MAIL_TO=bozena@iyc.com
  ENQUIRY_TO_EMAIL=bozena@iyc.com
  BOOKING_TO_EMAIL=bozena@iyc.com
  CONTACT_EMAIL=enquiries@ladymarcelle.co.za
  SMTP_HOST=smtp.ladymarcelle.co.za
  SMTP_PORT=465
  SMTP_SECURE=true
  SMTP_USER=enquiries@ladymarcelle.co.za
  SMTP_PASS=<secret>
  SMTP_FROM="Lady Marcelle Website <enquiries@ladymarcelle.co.za>"
  SMTP_TLS_REJECT_UNAUTHORIZED=false

To update .env:
  1. Edit on server with nano, OR upload a new .env with pscp
  2. Recreate the container (stop/rm/run) so new env is picked up
  Rebuild is NOT required for env-only changes (run alone is enough if image exists).

----------------------------------------------------------------------
6. NGINX / SSL (RARELY CHANGED)
----------------------------------------------------------------------
Repo reference: deploy/nginx-ladymarcelle.conf
Server file:    /etc/nginx/conf.d/ladymarcelle.conf

After editing nginx:

  sudo nginx -t
  sudo systemctl reload nginx

HTTP → HTTPS redirect; HTTPS proxies to http://127.0.0.1:3000

Certs: /etc/letsencrypt/live/ladymarcelle.co.za/

If cert needs renewal (certbot usually auto-renews):

  sudo certbot renew
  sudo systemctl reload nginx

  sudo systemctl enable nginx --now
  sudo usermod -aG docker ec2-user

Upload project to ~/LadyMarcell-V1, create .env from .env.example,
install nginx conf, obtain SSL with certbot, then build/run Docker as above.

Security group must allow inbound:
